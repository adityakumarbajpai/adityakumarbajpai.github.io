2025 – 2026ITSM

ServiceNow Ticket Operations Suite

Role
Built and own it
Result
Hours of manual queue handling replaced every day

What it solves

Incident and RITM queues were watched by hand, the same web forms were filled in again and again, and reports were put together manually. It cost hours every day.

How it solves it

Python and Selenium drive the browser. The suite extracts the queues, completes the repetitive forms and emails scheduled reports through Outlook. Task Scheduler runs it unattended on Windows VMs.

Engineering detail
  • Works through ServiceNow's web interface with Selenium and Edge WebDriver, and sends its reports through Outlook with win32com.
  • The unassigned-ticket report starts every 5 minutes and a run takes about 2. A run still open at 4 minutes is force-terminated, so a stuck browser cannot block the next one.
  • Connection failures are detected at page load. The run exits cleanly and the next scheduled start begins fresh, with layered fail-safe exits behind that.
  • It shares one Python installation and one Edge driver with other automation on the same machines, so every change has to leave the neighbours untouched.

Python · Selenium · Edge WebDriver · ServiceNow · Task Scheduler · Outlook/win32com

2025 – 2026Filesystem

VoluMetric

Role
Rebuilt the scan engine
Result
Full-volume scan cut from about 46 s to about 4 s

What it solves

A filesystem inventory that walks every directory is slow. A full volume took about 46 seconds.

How it solves it

VoluMetric reads the NTFS Master File Table directly. 800,000+ records and 490,000+ file paths resolve in about 4 seconds, including hard links, junctions and symlinks, with zero unaccounted records and full parity with the directory walk.

Engineering detail
  • Reads the Master File Table through the Win32 API from PowerShell, in place of one filesystem call per directory.
  • Resolves hard links, junctions and symlinks, the cases where a file record and a path are not one-to-one.
  • Checked against the original directory-walk engine: full parity, and zero unaccounted records out of 800,000+.
  • Per-function logging, and a clean-up pass for empty cells in the CSV output.

PowerShell · NTFS internals · Win32 API

2025 – 2026Policy

Policy Change Apply Engine

Role
Designed and wrote it
Result
Policy changes land on offline servers, all or nothing

What it solves

Group Policy and Security Options changes had to reach Windows Server 2016 and 2019 fleets with no internet access. The change request names each policy the way gpedit shows it, not as a registry key.

How it solves it

One self-contained PowerShell 5.1 script. It resolves every policy name against the server's own ADMX files at runtime, applies only when every row maps, and writes a per-server report for aggregation across the fleet.

Engineering detail
  • Each server resolves the names against its own ADMX and ADML files at run time. A text pre-filter picks the candidate files and only those are parsed as XML.
  • That targeted lookup replaced a first version that inventoried every policy on the server and used too much CPU and RAM.
  • Security Options have no ADMX. The engine finds them in the server's own security-policy registration and applies them with secedit.
  • Runs as one BladeLogic job, with numbered exit codes and a report CSV shaped so a whole fleet aggregates into one file.
  • No modules and no internet needed, and nothing hardcoded: paths, language and tool locations come from the machine.

PowerShell 5.1 · ADMX/ADML · secedit · Windows Registry · BladeLogic

2025 – 2026Certificates

SAN switch certificate monitor

Role
Built it, then rewrote the collector for reliability
Result
Renewals flagged up to three months ahead

What it solves

Certificates on SAN switches in several regions expire on their own dates. Checking them by hand means logging in to each switch through a jump host.

How it solves it

A Python script drives the SSH sessions through the jump hosts, reads the expiry dates and writes a colour-coded Excel report: green above three months, amber from two to three, red under two. The flagged rows go out by email.

Engineering detail
  • Two hops per switch: SSH to a jump host with single sign-on, then SSH from there to the switch.
  • The first collector used an expect-style library that hung silently on the VM. I rewrote it on plain subprocess calls to plink, and it now collects every switch over one jump-host session.
  • Switches that fail on the first jump host are retried at the end of the run through a second one.
  • Reads three certificate expiries per switch and converts every timestamp to one time zone before comparing.
  • Delivers a timestamped Excel report, plus an HTML email of the flagged rows through Outlook.

Python · SSH (plink) · Brocade · Excel · Outlook

2025 – 2026Dashboard

Automation Opportunity Dashboard

Role
Designed and built it, shipped as versioned releases
Result
Put forward to executives for company-wide rollout

What it solves

The team's automation opportunities lived in an Excel tracker with no quick way to see status or patterns. CDN chart libraries are blocked on the network.

How it solves it

A single HTML file. It parses the workbook in the browser, draws every chart as hand-written SVG, cross-filters on click, and exports the filtered data to Excel and each chart to PNG. Reload the workbook and it refreshes.

Engineering detail
  • No libraries at all. The page reads .xlsx with native browser APIs and draws its own charts, because nothing can be loaded from a CDN.
  • Covers the automation pipeline across six technology towers, with status, owner, percent complete and a dated comment log for each opportunity.
  • Multi-select filter pills, and every chart filters the others on click.
  • The team keeps updating the Excel tracker they already had. Reloading the file refreshes the dashboard.

Vanilla JavaScript · SVG · HTML/CSS · Excel

2025 – 2026Learning

Learning and Certification Hub

Role
Designed and built it
Result
Row-by-row reading replaced by click-through drill-down

What it solves

Learning hours and certifications for 68 manager teams sat in two Excel exports that had to be read row by row.

How it solves it

A self-contained dashboard reads both workbooks in the browser. A small loopback-only PowerShell server serves it and shuts down when the tab closes. Click any figure to drill down, level after level, and export exactly the rows on screen.

Engineering detail
  • Two audiences on one page: large headline numbers for the executive board, then the working dashboard for engineers and team leads.
  • Three tabs: learning hours, certifications and the certification roadmap.
  • Drill-down is a stack of panels of any depth, from programme to team to sub-team to individual records. Each panel exports its own rows as a real .xlsx.
  • It uses the workbooks' own categories unchanged, so an export always matches the source.
  • Starts with one double-click and nothing is uploaded: the server only listens on the local machine.

Vanilla JavaScript · SVG · PowerShell · Excel
